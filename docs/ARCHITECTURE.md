# Архитектура WhisperGUI

## Состав пакета

`app/` содержит исходники Python, `requirements.txt`, `WhisperGUI.spec`, скрипт сборки и `tests/`. Соседняя папка `diarization/` содержит `wespeaker_fixed.xml` и `wespeaker_fixed.bin`. Большие веса Whisper и Qwen в исходный пакет не входят: их ищут рядом с `app/` или устанавливают отдельно. `app/dist/` и `app/build/` — результаты сборки, а не исходный код.

| Модуль | Ответственность |
| --- | --- |
| `main.py`, `main_window.py` | Запуск Qt, настройки окна, выбор файлов и моделей, связь с фоновыми задачами. |
| `media_loader.py`, `transcriber.py` | Извлечение звука из видео через FFmpeg; загрузка аудио, распознавание, сохранение TXT. |
| `diarizer.py`, `speaker_renamer.py` | Выделение голосовых признаков WeSpeaker, группировка спикеров, назначение имён и прослушивание фрагментов. |
| `ai_dialog.py`, `llm_processor.py`, `prompt_library.py` | Локальная обработка расшифровки Qwen, библиотека промптов, сохранение документа. |
| `settings.py`, `model_manager.py`, `model_installer.py`, `model_updates.py` | Изоляция профилей, поиск моделей, Qt-интерфейс обновлений и независимый от GUI движок проверки/установки. |

## Поток данных

1. `MainWindow` получает список аудио/видеофайлов и запускает `Transcriber` в `QThread`.
2. Для видео `MediaLoader` создаёт PCM WAV 16 кГц; обычное аудио передаётся дальше напрямую. `librosa` загружает и приводит звук к 16 кГц. `WhisperPipeline` обрабатывает его кусками (по умолчанию 5 минут), а результаты получают абсолютные таймкоды.
3. Если включена диаризация, `OpenVINODiarizer` вычисляет признаки WeSpeaker для речевых участков и группирует их. Для двух изолированных каналов предусмотрен отдельный режим по энергии каналов. Каждой строке Whisper назначается спикер с наибольшим временным пересечением; результат сохраняется как UTF-8 TXT.
4. `SpeakerRenameDialog` может заменить `SPEAKER_*` на выбранные пользователем имена в сохранённом TXT и воспроизвести фрагмент исходной записи.
5. `AIProcessingDialog` запускает `LLMProcessingWorker` по готовому TXT/MD. Он нормализует таймкоды, при необходимости делит длинный текст на части, запускает локальную Qwen через `LLMPipeline` и сохраняет Markdown, TXT или HTML. Для некоторых встроенных промптов есть дополнительный проход сверки с исходным текстом; ссылки на реплики сопоставляются с реальными таймкодами программно. Смысловые выводы всё равно требуют проверки человеком.

## GPU и модели

Нейросетевой вывод Whisper, WeSpeaker и Qwen жёстко направлен на OpenVINO `GPU`; `Settings.load()` также принудительно задаёт `device=GPU`. Группировка голосовых признаков в `diarizer.py` выполняется через scikit-learn на CPU. Проект ориентирован на совместимый Intel GPU и драйвер OpenVINO; режим CPU для нейросетевого вывода не реализован. При ошибке загрузки Whisper используется установленный вариант FP16 из менеджера либо старая соседняя папка с именем `-fp16-ov`, если она существует; устройство остаётся GPU.

Пути по умолчанию для исходного запуска вычисляются относительно родителя `app/`: `turbo-gpu/whisper-large-v3-turbo-int8-ov`, `diarization/wespeaker_fixed.xml` и `llm-models/Qwen3-8B-int4-ov` (доступен также Qwen3-14B). Новые загрузки используют `%LOCALAPPDATA%\WhisperGUI-Beta\models\_versions/<key>/<fingerprint>`. Установщик берёт модели из официальных репозиториев OpenVINO и WeSpeaker на Hugging Face, фиксирует ревизию, поддерживает докачку и проверяет размер/хеш файлов. Для WeSpeaker ONNX конвертируется в FP16 IR с входом `[1, 200, 80]`; компактный исходный IR также включён в релиз.

`model_updates.py` не меняет настройки: возвращает неизменяемую проверенную папку. UI атомарно переключает `model_paths` и сохраняет предыдущий путь в `model_previous_paths`. До переключения выполняется GPU-проверка. Отмена, ошибки сети, недостаток места и несовместимость оставляют прежние файлы активными. Хеш нужных файлов, а не один SHA репозитория, определяет наличие обновления. Старые модели с неизвестным происхождением не выдаются за подтверждённую версию.

## Настройки и выходные файлы

`%APPDATA%\WhisperGUI-Beta\settings.json` хранит параметры и выбранные пути; `%APPDATA%\WhisperGUI-Beta\prompts.json` — пользовательские промпты. Локальные модели по умолчанию лежат в `%LOCALAPPDATA%\WhisperGUI-Beta\models`, кеш Qwen — в `%LOCALAPPDATA%\WhisperGUI-Beta\llm_cache`, журнал ошибки запуска — в `%LOCALAPPDATA%\WhisperGUI-Beta\startup_error.log`. При первом запуске бета копирует профиль стабильной версии из `WhisperGUI`, сохраняя старые ссылки на модели для чтения, но не изменяет исходный профиль и его файлы.

Отдельная расшифровка по умолчанию создаётся рядом с исходником как `{original_name}_transcript.txt`; общий режим создаёт `transcript_multi.txt` (для одного файла — `{original_name}_multi.txt`) в папке первого исходника. Можно выбрать другую существующую папку сохранения. Результат ИИ помещается рядом с расшифровкой с суффиксом промпта; при совпадении имени добавляется числовой суффикс. Временный WAV для видео удаляется после обработки, если не включено сохранение извлечённого звука; при сохранении он получает имя вида `{original_name}_audio.wav` рядом с видео.

## Границы текущей реализации

- Нужен GPU и достаточно памяти для выбранных моделей; наличие совместимого оборудования нельзя вывести из исходников. Qwen необязательна для распознавания.
- Диаризация эвристическая: короткие или перекрывающиеся реплики, ошибочные таймкоды и похожие голоса могут приводить к неверным меткам. В общем файле из нескольких записей автоматическое назначение имён пропускается.
- Режим сохранения `ask` в `transcriber.py` сейчас выбирает папку исходника: диалог выбора при сохранении не вызывается. Обычный отдельный TXT с тем же именем перезаписывается.
- `speaker_renamer.py` разбирает таймкоды вида `MM:SS`, а `transcriber.py` после одного часа выводит `HH:MM:SS`; переименование строк длинных записей может не сработать.
- Проверка фактов в Qwen опирается на текст расшифровки, который сам может содержать ошибки. Протоколы и поручения следует проверять перед использованием.
