# Работа с проектом

## Репозиторий и источники

- Корень текущей папки является единственным рабочим Git-репозиторием. Код находится в `app/`, документация — в `docs/`.
- Не восстанавливайте параллельные рабочие копии `WhisperGUI_Development`, `WhisperGUI_Distributable` или `WhisperGUI_Diarization`.
- Не включайте в коммиты `local-data/`, записи, расшифровки, пользовательские документы, персональные настройки, секреты, большие модели, сборки и готовые релизы.
- Два компактных файла `diarization/wespeaker_fixed.xml` и `.bin` нужны для сборки и намеренно отслеживаются Git.

## Git-режим

- Перед изменениями проверяйте ветку и `git status`; сохраняйте чужие незакоммиченные изменения.
- Стабильная версия — `release/1.5` и тег `v1.5.0`. Разработка — `beta/2.0`. Тег `v2.0.0-beta.1` отмечает выпущенную первую бету.
- Для новой задачи создавайте от актуальной `beta/2.0` отдельную ветку `feature/...`, `fix/...` или `chore/...`, если пользователь не указал другую.
- Завершённые изменения оформляйте небольшими смысловыми коммитами только с файлами текущей задачи. Обычный ответ на вопрос или диагностика не требуют изменения кода или коммита.
- Перед коммитом проверяйте diff и запускайте проверки, соответствующие изменению. В итоговом сообщении указывайте ветку, коммиты и результат проверок.
- После успешной проверки можно перенести свою завершённую ветку в `beta/2.0` через fast-forward, если это не затрагивает чужую работу. При расхождении истории оставьте рабочую ветку и сообщите об этом.
- Не переписывайте выпущенные теги, коммиты и историю без прямой просьбы пользователя. Не используйте разрушительный reset или принудительную отправку.
- Не публикуйте код, не создавайте удалённый репозиторий и не выполняйте push без явного запроса пользователя. Локальная работа в Git не означает разрешения публикации.

## Проверки и релизы

- Из `app/`: `python -B -m unittest discover -s tests -v`; окружение — Python 3.10 с зависимостями проекта.
- Запуск GUI: `python main.py --smoke-test`. Для независимых проверок изолируйте APPDATA/LOCALAPPDATA и временные данные в игнорируемой `local-data/validation/`.
- Проверки GPU, загрузки моделей и сборки описаны в `docs/DEVELOPMENT.md`. Не выдавайте короткий тест загрузки за проверку качества распознавания.
- Нейросетевой вывод Whisper, WeSpeaker и Qwen должен оставаться на Intel GPU/OpenVINO. Не добавляйте скрытый переход на CPU.
- Стабильный релиз и бета имеют отдельные настройки. Старые рабочие модели нельзя заменять до успешной проверки новой версии.
- Для нового релиза согласуйте номер в `app/app_version.py` и `app/version_info.txt`, обновите историю изменений и создайте новый комплект. Не перезаписывайте `WhisperGUI_Releases/1.5.0` или другие выпущенные релизы.
- Передавать пользователю нужно весь релизный ZIP: EXE требует соседней папки `_internal`.

## Уборка

- Личные файлы сохраняйте в `local-data/`. Git не является резервной копией этих данных.
- Если пользователь просит удалить устаревшие файлы, используйте корзину Windows, проверив точные пути и отсутствие уникальных нужных данных. Корзину не очищайте.
